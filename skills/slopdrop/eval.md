# Eval

Run this after the work, before returning it. Answer each line pass or fail. If any fails, fix and run again.

## Honesty

1. Does every finding name a file and line, or explain why it cannot?
2. Is every score backed by a reason: the worst finding in that dimension, or what earned the 4?
3. Are estimates marked `~`, and is performance reported as `Not profiled` unless it was measured?
4. Does the report list what was not checked, including performance?
5. Did you avoid claiming a check you did not run?
6. Did you refuse to guess whether AI wrote the code or copy?

## Judgment

7. Did you look at the running product, or say that you could not?
8. Did you form your own read before running the detector?
9. Is every detector hit verified in context before it became a finding?
10. Did you rank a blocked or slowed task above any visual issue?
11. Is the verdict one sentence about this product, not a generic label?
12. Did you say a healthy screen is healthy instead of inventing problems?

## Treatment

13. Did you name the case (heavy, light, healthy) before editing?
14. For a heavy case, did you write the five-line direction and wait, unless told to proceed?
15. Did you fix tokens and shared components before screens?
16. Did you keep frequently used controls, gestures, and URLs in place, or ask first?
17. Did you leave business logic, data flow, and analytics untouched?
18. Did you avoid adding a dependency without asking?
19. Does the diff stay inside the agreed screens and the shared code they need?
20. Did the after pass the cover-the-logo test and the neighbor test?
21. Did the number of containers and colors go down, not up?
22. Does every color still carry meaning, and does every dot have a status a color-blind user can read?
23. Does the screen meet the floor: targets, contrast, text scaling, safe areas, states, labels?
24. Did you re-run the detector on changed files and explain every kept hit?

## Copy

25. Does the edit preserve the writer's point without adding claims, examples, stats, quotes, or opinions?
26. Does it preserve the writer's vocabulary, cadence, bluntness, humor, uncertainty, and digressions?
27. Did you leave strong human sentences alone instead of tidying every paragraph?
28. Is the cutting proportional to the actual slop, with no aggressive compression that strips character?
29. Are binary contrasts, faux-insight setups, colon reveals, throat-clearing, importance puffery, weasel attribution, synonym cycling, fake-profound kickers, and summary recaps gone?
30. Are banned words, empty adverbs, and filler phrases removed unless quoted as examples?
31. Is formatting follow the content, with no emoji headings, decorative bold, or bullets that should be prose?
32. Are em dashes absent in short copy and at most one or two in longer copy?
33. Does the output include the full edited text and a short **What changed** section?
34. For a detect request, does the response name each pattern with a quoted line and a short fix, without rewriting or scoring?

## Spatial

35. Was the review done on a device, or clearly marked as code-only?
36. Are angular sizes measured (text ≥ 1.2°, targets ≥ 2°), not estimated from pixels?
37. Are comfort, recenter, seated mode, and input parity checked?
38. Is passthrough contrast checked against an opaque surface?
39. Is the frame budget reported as measured, or marked unmeasured?

## Sync

40. Did you read the chart before asking questions it already answers?
41. Did you pull changes since your last cursor before re-diagnosing a screen?
42. Did you record the visit and the confirmed findings?
43. Did you propose waivers instead of assuming them, and leave approval to a human?
44. On a conflict, did you re-read and retry with a new idempotency key instead of overwriting?
